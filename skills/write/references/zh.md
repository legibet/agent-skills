# 中文

## 句子

### 缩句和电报式短句

句子写完整。读者需要知道是谁在做事时，把主语写出来。句子之间的因果、转折和递进关系，用连接词写出来。用冒号引出一串名词短语、用分号串起几个短语、看不出谁在做事的短句，都改写成完整的句子。顺着一个意思往下说的长句照常写完。要写得简短，就删掉读者不需要的内容，不要压缩句子。

- 反例：结论：命中率高，成本可控；缺点：首轮慢。
- 改成：缓存命中率高，所以长对话的成本仍然可控。代价是第一轮请求较慢。

### 抽象主语、名词化和指代不清

让做事的人或具体的东西作主语，动作用动词表达。“X 的价值在于 Y”“关键在于 Z”“区别在于 W”用抽象名词作主语，“对 X 进行优化”把动作变成了名词，读者要自己推断是谁做了什么。

“这”“该”“其”“它”离所指的对象很远，或者前面有几个可能的对象时，把对象的名字写出来。工具、组件或概念第一次出现时，如果读者不认识，交代它是什么。

- 反例：这个缓存的价值在于减少了重复计算。
- 改成：这个缓存减少了重复计算。
- 反例：我们对查询逻辑进行了优化。
- 改成：我们优化了查询逻辑。
- 反例：调度器把任务分给工作进程，它失败后会重试三次。
- 改成：如果工作进程执行失败，调度器会重试三次。

### 长定语

中文的定语只能放在名词前面。一长串限定堆在“的”字前，读者要先读完才知道谁在做什么。先找出真正做事的人或物，把它和动作放到前面，原因、时间、条件接在后面。复杂的关系可以用长句讲完，只要主干早点出现。

- 反例：在经历了长达数月且始终没有稳定产出的反复调参之后，最终促使团队换掉这套方案的，是一次线上超时。
- 改成：这套方案调了好几个月，产出一直不稳。后来线上超时了一次，团队才把它换掉。

## 语气和表态

这一组写法在内容前后加了表态、铺垫或防御，没有给读者新的信息。判断时看去掉这句或这个词以后，读者少知道了什么。

### 叠甲和防御句

有依据的判断直接写出来。“可能”“通常”“在一定程度上”“从目前来看”只用在确实不确定的地方。证据说明不了的结论不写，“尚不足以说明 X”“不能据此认为 X”这类句子也不写。读者不会提出的质疑，不用预先回答。先让步再转折的“这话不算错，但……”，改成直接的判断。如果读者问的正是 X 是否成立，“证据不支持 X”就是答案，照常写。

- 反例（有依据却降调）：公开结果显示，这类配方通常能换来更高的能力密度。
- 改成：这类配方能换来更高的能力密度。
- 反例：文章可以预测远程服务会成为主要场景，但目前列出的证据还不足以说明本地场景会持续萎缩。
- 改成：文章可以预测远程服务会成为主要场景。

### 判断抢在事实前面

“问题很直接：”“原因很朴素：”这类引子先下评价，再给事实。删掉引子，直接写事实。

- 反例：问题很直接：接口没有做鉴权。
- 改成：接口没有做鉴权。

### “不是 A，而是 B”

这种句式先替读者立一个他们没有的误解，再推翻它。同一种写法还有“不是 A，是 B”“并非 A 而是 B”“不在于 A 而在于 B”“看似 A 实则 B”“你以为 A，其实 B”“A 已经不是瓶颈，B 才是”。直接从正面说 B。读者确实会以为是 A 时，才这样写。“不只……还……”这种递进照常用。

- 反例：代码生成不是瓶颈，评审才是。
- 改成：现在的瓶颈是评审。

### 讲课口吻

“你得先明白”“你会发现”这类话是讲课的口吻，还替读者预设了反应。改成直接陈述事实。

- 反例：你会发现，缓存命中以后，延迟明显下降了。
- 改成：缓存命中以后，延迟明显下降。

### 谈文字本身的句子

宣告结构、给内容贴标签、开篇自我说明、叙述交叉引用、段落之间的桥接句，换成它指向的内容。

- 反例：先给最短结论，就四句：
- 反例：拿一组具体数字看会更直观。
- 反例：X 也是容易被低估的部分：
- 反例：值得注意的是，……

## 用词

用这个领域里平常、准确的说法。自造的名称、生造的口语缩略、套话和黑话、从英文直译的动作动词，以及文档和论文里的口语词，都换成平常的书面说法。没有通行中文译名的术语保留英文，不要自己造译名。自造的名称会被读者当成通用术语，又查不到。聊天和便条可以用口语。

- 反例（自造的名称）：软水位 / 硬水位、唯一通道
- 反例（自造的名称）：这几条是项目的家规。
- 改成：这几条是项目规则。
- 反例（生造的口语缩略）：上下文不崩、成本不爆。
- 改成：上下文不会乱，成本可控。
- 反例（生造的口语缩略）：容差要拍。
- 改成：容差需要凭经验定一个值。
- 反例（套话和黑话）：赋能、抓手、闭环、底层逻辑、事半功倍、开箱即用
- 反例（文档和论文里的口语）：其实、说白了、居然
- 反例（直译的动作动词）：你这几条我都接住了。这个论证被击穿了。更锋利的重构：
- 改成：你这几条我都收到了。这个论证不成立。更准确的说法是：

## 标点

冒号用来引出前面提到的列举、解释或引文，比如“支持三种格式：JSON、YAML 和 TOML”。不要用冒号代替“是”“因为”这类词。

- 反例：这次失败的原因：配置文件路径写错了。
- 改成：这次失败是因为配置文件路径写错了。

分号只用在结构相同、关系紧密的并列分句之间，其他情况用句号分开。分号后面接“但”“而”这类转折词时，改用句号。

- 反例：……也决定后训练有没有可以利用的空间；但它没有决定这个模型会不会听指令。
- 改成：……也决定后训练有没有可以利用的空间。但它没有决定这个模型会不会听指令。

引号用来标出引用的原话和专有名称。用引号表示强调或反讽时，读者要猜作者的意思，改成直接的说法。

- 反例：大模型最擅长“翻译”。防止 Agent 通过改标准来“提升”分数。
- 改成：大模型最擅长按规格说明做对照实现。防止 Agent 通过改标准来刷分。

不用破折号。需要引出解释或转换话题时，基于场景用逗号、冒号、括号，或者另起一句。
