# Issue stage

The issue stage is diagnosis: figure out what is wrong, why, and what to do about it.

## Capture

Record the problem as soon as it appears, while the details are fresh.

## Diagnosis

Reproduce the problem first. Keep verified facts and speculation clearly separated: anyone picking the issue up later must be able to tell what is confirmed and what is still a guess.

## Format

An issue document can be very short:

- **Problem**: the symptoms, how to reproduce it, and the impact.
- **Possible solutions**: options with their tradeoffs, and the chosen one. Optional.

## Moving on

- **Fix directly**: when the fix is simple, execute once the direction converges.
- **Plan**: when the issue is complex, converge it into a plan; read `references/plan.md` when ready.
- **Won't fix**: if the diagnosis concludes the problem is not worth fixing, record the conclusion and reasoning in the issue document, then stop.
